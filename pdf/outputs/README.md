# PDF export test renders

Every PDF-producing code path in `kapwa-server` is invoked with representative
data and rendered to PNG so the output can be reviewed without a running stack.

- **PDFs:** generated by the real builders and services (repository/service
  dependencies are stubbed with fixture data).
- **PNGs:** rendered with `pdftoppm -r 110`. Single-page exports use
  `<name>.png`; multi-page exports use `<name>-pN.png`.

## Automated layout checks

`kapwa-server/scripts/render-pdf-samples.mjs` rebuilds exports 01–05 and runs two
objective checks against every rendered page (six pages):

1. **Overlapping text** — `pdftotext -bbox` word rectangles are compared
   pairwise; any pair whose intersection exceeds 25% of the smaller rectangle is
   a collision.
2. **Off-page text** — every word rectangle must fall inside its page box.

The script prints one inventory row per document, lists the offending words on
failure, and exits non-zero if either check fails. Exports 08, 09 and 13 are not
re-audited here (see above); their stored pages were checked by the original
harness.

Labels that could collide with a neighbour are shrink-fitted to their cell, and
cell values wrap and clip inside their own cell, so the layout stays collision
free regardless of the loaded data.

## Paper sizes

`Certificate of Eligibility` and `Petty Cash Voucher` are printed on cut strips
of bond paper, so they use custom page sizes (see `COE_PAGE` / `PCV_PAGE` in
`cases/case-documents.builder.ts`):

- Certificate of Eligibility — 21 cm × 7 cm (landscape strip)
- Petty Cash Voucher — 21 cm × 14 cm (landscape strip); **Part II
  ("to be filled up upon liquidation") is deliberately left blank** and is only
  completed at liquidation time.

## Regenerating

From `kapwa-server/`:

```bash
npm run build && node scripts/render-pdf-samples.mjs
```

The renderer requires poppler-utils (`pdftoppm`, `pdftotext`) on `PATH` and
exits with a clear message if either tool is missing. Exports 08, 09 and 13 were
produced by the original temporary harness, which was not committed; re-create
them from the export services or drive the same builders through the existing
Jest specs in `src/**/*.spec.ts`.
